# 患者微信小程序（开发预览）

原生微信小程序工程。提供 dev/test 患者登录、本人资料与预约列表、就诊详情/已发出结算、复诊计划列表/详情、真实门店/牙医/项目目录、候选时段、新增/改约/取消。页面始终标记为开发联调，不提供 patientId 登录，也不模拟预约成功。

## 本地预览准备

1. 导入本目录 `D:\牙医\miniprogram` 到微信开发者工具。项目配置中的 AppID 为 `wx4ce7918a5993372b`；本轮未运行工具核实导入与编译结果。
2. 在 [环境配置](config/environment.js) 中按需修改 API 地址。默认值是启动器实际配置的 `http://127.0.0.1:18083/api/v1`。
3. 按项目的 `admin-web/scripts/start-dev.cjs` 启动本地依赖和 dev/test API。该启动器使用独立的 MySQL 端口 `13318`、API 端口 `18083` 和 Vite 端口 `5178`；运行前会检查端口及已记录实例，已有实例时要求先按配套 stop 脚本处理。启动器不清理已存在数据目录，检测到非预期内容会拒绝初始化。
4. 患者测试登录名为 `demo-patient`。密码由启动器创建并保存在 `D:\牙医\admin-web\.runtime\credentials.json` 的 `demo.password` 字段；只在本机安全查看/粘贴到登录框，不要复制到聊天、命令输出或日志。启动器控制台只给出凭据文件路径，不打印密码。密码只在登录请求中使用，不保存；会话令牌存本机小程序存储，退出或收到 401 时清除。
5. 微信开发者工具需启用本地网络请求调试设置；不要将该设置用于正式发布。模拟器的 loopback 可指本机，真机上的 `127.0.0.1` 指手机本身，不能连接桌面服务。

## API 与页面范围

- `POST /api/v1/dev/patient/sessions`：仅开发/测试患者账号密码登录。
- `GET /api/v1/patient/profile`：会话本人资料和预约限制状态。
- `GET /api/v1/patient/appointments`：本人最近预约列表，最多100条。
- `GET /api/v1/patient/appointments/{id}`：本人预约、已确认项目及已发出费用；费用只展示服务端原始十进制字符串，保留零价行。
- `GET /api/v1/patient/followup-plans?status=all&afterId&limit=30`：本人复诊计划摘要，使用服务端 `items`、`hasMore`、`nextAfterId` 和 `asOfDate` 分页。
- `GET /api/v1/patient/followup-plans/{planId}`：本人单项复诊计划摘要。只显示服务端计划状态、逾期标记、建议日期和建议内容；不读取员工联系记录/快照，不将任意预约当成该计划完成。
- `POST /api/v1/patient/followup-plans/{planId}/appointments`：从待复诊计划安排本次复诊。复用 SelfBooking 请求字段，患者身份由会话取得；`planId` 只放路径，不进入请求体。
- `GET /api/v1/patient/clinics`、`/patient/dentists?clinicId`、`/patient/availability?clinicId`、`/patient/treatment-types`：真实门店、有效出诊、可约窗口/占用及参考目录。
- `POST /api/v1/patient/appointments`：新增；`POST /api/v1/patient/appointments/{id}/reschedule`：改约；`POST /api/v1/patient/appointments/{id}/cancel`：取消。
- `DELETE /api/v1/sessions/current`：退出会话。

## 时段与操作规则

- 候选起点每30分钟展示一次；患者可选30/60/90/120分钟，改约默认沿用原时长。每个时长都逐段检查真实出诊窗口、同牙医跨店占用、本人未结束安排和服务端 `asOf`/当前时间，不把整段窗口显示为空闲。提交时服务端仍重新检查。
- `patientOccupied` 不含预约ID，所以改约候选保守避开本人的所有未结束安排，包括当前原约；界面会说明这一点。
- 新增/改约固定 `appointmentNo`，取消/改约固定版本和原请求体。遇到超时或服务端5xx会保留原请求、操作号与患者归属；只可重试原请求。待核实期间阻止新写操作和退出，成功或明确失败后清除待处理项。
- 复诊详情只在服务端状态为“待复诊”时显示“安排本次复诊”。预约页从会话重新读取计划并核验计划ID、本人归属和状态；建议日期/事由独立显示，不自动填为治疗需求，门店和牙医由真实可约资源选择。关联新增使用专用路径，普通新增和现有改约仍沿原路径。未知结果重试存储的原路径、操作号和原请求体；成功响应必须带回相同 `followup_plan_id`，否则提示核对、不再次提交，并保存按本人/计划隔离的复核标记，后续打开该计划仍会暂停自助关联。
- 预约办理页在无会话、401 或账号令牌切换时先清空本人预约详情和输入；资源、资料与写入响应都校验页面存活及当前会话。切换到另一患者时，待核实信封仍按原患者保留在本机，但不展示操作类型或请求内容，也不会提供重试；只有原请求返回明确结果才清除。
- “我的复诊计划”仅调用患者复诊列表/详情路由。状态筛选为全部、待复诊、已完成、已取消；建议日按DATE原样展示，逾期与计划状态直接取服务端，列表显示服务端上海业务日期。支持游标分页；翻页失败保留原游标，跨日时重置并从第一页刷新，并发翻页只发一个请求。页面对无会话、401、切换账号和卸载后的迟到响应做清屏/隔离处理。
- 取消/改约前说明3小时规则。受限时显示服务端限制起止/原因和真实门店电话；可继续查询与取消，不能自助新增/改约。到诊、诊疗和结算边界由服务端最终判定。
- 时间用Asia/Shanghai展示；参考价格仅显示服务端十进制字符串，明确不代表本次收费；不提供支付、短信或假微信身份。

## 正式微信身份接入清单（仅规划，未实现）

源码配置含非敏感 AppID（`project.config.json`），客户端没有 `wx.login`、`code2Session` 实现，也没有 AppSecret。当前患者登录仍是 dev/test 的 `POST /dev/patient/sessions` 账号密码流程，不能作为微信身份认证或生产登录。

接入前需完成：

- 后端新增受控的登录码换会话流程：小程序只调用 `wx.login` 取得一次性 code 并发送给后端；后端使用 AppID 和仅保存在服务器环境/密钥管理器中的 AppSecret 调用微信服务端接口，再由后端签发与现有患者档案对应的患者会话。禁止在小程序包、前端配置、日志或聊天中放置 AppSecret。
- 先定义现有患者账号的可靠认领/绑定合同和核验流程。手机号可由家属共用，不能以手机号自动合并患者、自动创建患者或自动绑定账号；需要单独的业务确认后再实现。客户端传来的 patientId、昵称或手机号都不能作为本人身份凭据。
- 明确登录会话的过期、续期、退出、撤销和账号解绑行为，并继续由服务端从会话确定本人及授权。不要将 dev/test 登录作为失败回退路径。
- 冻结开发、测试、生产各自的 HTTPS API 域名和微信合法 request 域名配置；生产配置不可指向本地 loopback，也不可依赖开发工具的跳过校验选项。现有 `config/environment.js` 仍指向本地 `127.0.0.1:18083`。
- 完成适用的主体资质、服务类目、隐私政策/个人信息处理告知、微信隐私保护指引与用户授权交互、请求域名校验、提审和发布检查；记录 AppID 所属主体和环境，先在测试账号/预览版本验收。
- 单独审查患者资料、预约、诊疗与费用页面的最小必要展示，以及日志、崩溃报告和第三方 SDK 的数据收集范围。

根据既有环境交接信息，生产 HTTPS API 的 dev/test 登录路由返回 404；本轮未访问该生产 API验证。保持当前 dev/test 登录及本地 API 地址原样，不将正式入口改指向 dev 路由。该清单仅列源码缺项和前置决策，本轮没有实现微信认证、患者绑定、自动建档、权限/数据库扩展或服务器配置。

## 本地静态/请求夹具

在项目根目录运行 `node scripts/verify-wx-request.cjs`，验证 API 地址、wx.request 封装、会话变更/401 清理、候选算法、待处理写入、预约页账号隔离和患者复诊计划分页/详情。该夹具使用内存响应，不连接后端、不验证微信页面渲染。

本地服务已启动时，可运行 `node scripts/smoke-local-api.cjs` 对接一键启动器的真实 dev/test API。脚本从 `admin-web/.runtime/credentials.json` 读取已有 demo 密码，不输出密码；它会登录、执行本人只读请求、退出并确认旧会话返回401，不创建预约或结算记录。完成后从 `admin-web` 运行 `node scripts/stop-dev.cjs`。

`node scripts/smoke-booking-flow.cjs` 已准备真实本地开发库的新增→精确重放→改约→精确重放→取消→精确重放联调流程，但**本轮未执行**：自动审批两次拒绝预约记录写入，理由是授权来自委托任务而非直接用户确认。不要用其他脚本或方式绕过。只有取得用户直接批准后，才可从 `admin-web` 启动本地服务并执行；完成后从 `admin-web` 运行 `node scripts/stop-dev.cjs`。本轮的真实 API 检查限于只读请求。
